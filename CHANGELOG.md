## 0.7.6 development — Sim-to-Sim responsiveness

- Added `SimResponseDecision`, the Sim-to-Sim counterpart of `ShouldReplyDeterministic`: every party line that becomes visible is now re-evaluated to decide whether another present Sim should answer it. Unlike the player-line gate it returns a graded urge rather than a boolean - a named address or a question is `Strong`, an opinion / disagreement / anomaly reaction is `Normal`, an ordinary substantive statement is `Weak`, and tactical spam, slash commands, trivial acknowledgements and short filler are `None`. It is pure, IO-free, and takes the speaker and the live party roster as parameters; no Sim or player identity is hardcoded.
- Root cause of the "party Sims barely answer each other" behaviour: continuation required `ConversationTurnGuard.HasConversationalHook`, whose keyword/question/name list treated most ordinary Sim statements as no hook at all, which forced continuation momentum to exactly 0.0 and ended the thread at one line. On the lines that did pass, the surviving probability was `SimToSimChance (0.60) * 0.55 = 0.33` for the very first answer, so even hooked threads usually stopped immediately.
- `AmbientCadence.ContinuationChance` now takes the graded urge (the old boolean overload is kept and maps to `Normal`/`None`, so existing behaviour for callers and tests is unchanged). A line that clearly invites an answer now draws one with high probability, a plain statement still only sometimes does, and the per-reply decay and Lively/Quiet presets are preserved.
- `SimToSimChance` is now normalised around its 0.60 default before being applied, so the graded probabilities are what actually runs out of the box instead of being cut by a setting the player never changed. The setting still moves the dial in both directions.
- Unified the response cap on `SimResponseDecision.MaxResponsesPerLine` (3). One party line may now draw up to three Sim responses on every path: player-directed replies (answer + two), autonomous openers, `/dsbanter` (`ManualTailReplies` raised from 1), and vanilla-Sim continuations (raised from 1). Each turn past the first is still earned individually by the urge gate plus the momentum roll, so the cap remains a ceiling, not a target - and the existing staleness, topic-change, membership, duplicate, and grounding guards are all untouched.
- Added deterministic self-test coverage for the new gate and the graded momentum curve, wired into both the standalone regression runner and `/dsguardtest`.

## 0.7.6 development — deterministic reply gating / grounding hardening

- Added `ShouldReplyDeterministic`, a pure, session-agnostic gate evaluated BEFORE classification, retrieval, or generation for a direct player party-chat line. A line that does not carry a real conversational hook (a question, an interrogative phrase without "?", an explicit Sim addressee, or a notable-event reaction) no longer triggers the semantic classifier or an LLM reply at all; it still becomes ordinary heard conversation exactly as before (recording was already independent of the reply decision) and can still inform later autonomous chatter. This is evidence-backed by the local real-packet prompt labs (V3-V5): a deterministic gate reused unmodified across those labs scored 13/13 real fixtures, 20/20 paraphrases, and 8/8 arbitrary-unseen-party-name cases, and a full ShouldReply-then-classify pipeline scored 100% end-to-end on a 106-case combined corpus while eliminating roughly a third of classifier calls. The gate takes the player's own name and the current live party roster as parameters; no Sim or player identity is hardcoded anywhere in it.
- `QueuePartyChatResponse` now evaluates this gate immediately after building the world snapshot, before selecting a speaker or invoking the classifier, unless the caller already guarantees a response (`forceResponse`).
- Added `RecentEventQuestionPolicy`, a deterministic handler for "how did that last fight go?"-style questions when Deep Sims has no verified completed-encounter result. Previously the model was asked to answer anyway with an instruction to admit uncertainty; the real-packet labs found this does not reliably stop the model from inventing a result, a cause, another Sim's presumed knowledge, or a promise to go investigate. When the authoritative answer is genuinely unknown, Deep Sims now returns one of a small, deterministically-selected honest-uncertainty line directly - zero Ollama calls for that turn - rather than asking the model to improvise around a gap it cannot fill.
- Removed the second, cosmetic-only LLM retry pass ("Rewrite the whole thought as..." for an overlong/incomplete/voice-guard-flagged reply that had already passed grounding). That pass could - and once did in practice - change what an already-accepted, already-grounded reply actually claimed while still satisfying the length/voice checks that gate it, because those checks validate length and voice, not fidelity to the original content. An overlong reply is now trimmed deterministically to the largest whole-sentence prefix that fits the reply budget; an incomplete or voice-invalid reply, or an overlong reply with no safe whole-sentence prefix, now falls back to `NO_MESSAGE` instead of a second generation call. Deep Sims now spends at most ONE semantic LLM retry in the whole direct-reply pipeline (the existing grounding-rejection retry).
- `GroundingGuard` gained three additional unsupported-assertion categories found repeatedly in the real-packet labs: a present-tense first-person current food/meal claim ("I'm eating stew"), a present-tense first-person individual mana/health/stamina-level claim ("my mana is low"), and a confident causal explanation for an unexplained event with no supporting evidence ("they probably respawned", "another squad must have aggroed them"). Hypothetical/preference framing ("I'd go for something warm", "I'd rather save my mana") and a plain reaction with no stated cause ("yeah, that was weird") remain fully allowed - only a stated present-tense fact or a stated cause is gated.
- Fixed a sanitizer bug where a literal Roman numeral in ordinary text (e.g. "Artemis II", "World War II") could be corrupted into "...that item" because the vanilla-template-placeholder cleanup treated any standalone "II" as the leaked `II` item-placeholder token. The check now only fires when "II" is NOT immediately preceded by a capitalized word, which distinguishes a real proper noun from an actually-leaked bare placeholder.
- Reverted `PromptCaptureEnabled`'s compiled default back to `false` (it had been temporarily flipped on in source for an active local capture session); PromptCapture remains fully available, just opt-in via runtime config as designed, matching the existing deterministic test guard for this default.
- Added deterministic self-test coverage for all of the above (`ShouldReplyDeterministic`, `RecentEventQuestionPolicy`, the deterministic reply-shortening helper, the Artemis-II sanitizer regression, and the three new GroundingGuard categories), wired into the existing standalone regression runner.

## 0.7.5 development — single-model pipeline repair
